# FGA Character Popup

Shows a big floating character portrait on screen when that character speaks in chat, gets bloodied/healed/revived, or has a classified buff/debuff applied — visual-novel style, separate from the chat log itself.

Built for **Gadrielian Realm** (Foundry VTT V13/V14, dnd5e system) and the **FGA** (Fake Gaming Army) table — version `2026.09.29.03`.

## What it does

- When someone sends a chat message, this module finds the speaking character and pops their portrait up on screen for a few seconds.
- **Placement, size, flip, and fade timing are all GM-controlled** — there's no more "each player sets their own popup" option. What every player always chooses for themselves, in **Configure Your Popup**: which image shows on their own screen (portrait or token — a personal viewing preference), and their own character's chat bubble color and text color (properties of the character, not the viewer — see below).
- **Chat bubble color is tied to the speaking character, not the viewer.** Each player picks their own character's bubble color once in Configure Your Popup, and it's stored on that character — so every player sees the *same* color when that character talks, letting the table learn to recognize who's speaking by color alone (e.g. always red when Player A's character talks, always green for Player B's). Text color defaults to the exact inverse of the bubble color, but each player can also pick a custom text color of their own — handy for the odd bubble background where auto-invert lands on a muddy or hard-to-read result.
- The GM controls the **shared** rules in **Configure Popup Rules**: how long popups stay up, which kinds of messages trigger one (in-character chat, emotes, dice rolls, and whether GM/NPC-spoken messages count too), **"no timeout"** so popups stay on screen until another one replaces them, the bloodied red-aura rules, and whether the optional chat bubble is shown at all and how big it is (not its color — that's each character's own).
- A separate GM-only window, **Configure Character Appearance**, is a two-pane control panel: pick a target on the left (Shared Default, NPCs — Hostile/Neutral/Friendly, or any individual player character), then set that target's look on the right.
  - **Shared Default** — the size/position/flip/fade every player character uses. Always in effect, unconditionally — there's no toggle to turn it off, since it's the fallback every character resolves to unless it has its own override.
  - **NPCs — Hostile / Neutral / Friendly** — three separate buckets, grouped by each NPC's own token disposition (Foundry's built-in Hostile/Neutral/Friendly/Secret setting). Each can be left on the module's default look or given its own custom one.
  - **Individual characters** — every player character gets its own row, with two choices: follow the Shared Default, or a custom look just for that one character — for the occasional character whose popup needs to look different (a bigger portrait, a different position, etc.).
  - **Image source (portrait vs. token)** can still optionally be pinned by the GM on any of the above — but it defaults to "Inherit," meaning every viewer keeps picking their own art regardless, unless the GM deliberately pins one for a specific target.
- The GM can also flip on **"Show a red aura when a character or NPC is bloodied"** — when it's on, any popup for a character at or below a GM-set HP percentage (default 50%) gets a pulsing red glow around the portrait, and by default the popup **fires on its own the instant someone crosses into bloodied** — no need to wait for them to say something in chat.
- A second checkbox, **"Show a green aura when healed, or gold when revived from 0 HP"**, covers the other direction: the instant an actor's HP goes up, their popup fires on its own with a pulsing **green** glow (healed while already above 0 HP) — except when they were at exactly 0 HP and it's the healing that brings them back above 0, which shows a pulsing **gold** glow instead (revived). Only one of the two ever shows for a given heal — a revival is always gold, never both. Independent of the bloodied red aura; a character healed back up to 40% HP (still "bloodied" by the threshold) shows green, not red, since the heal is the more relevant thing happening in that moment.
- A third GM-only window, **Configure Status Icons**, lists every condition the system knows about (Poisoned, Stunned, Invisible, Hasted, and so on — 55 in all) with its own icon and a Buff / Debuff / Off classification for each (pre-filled with sensible defaults, yours to adjust). Two master switches — "Show buffs when applied" and "Show debuffs when applied" — decide whether each whole category is actually shown. The instant a classified condition is newly applied to a character (never when it's removed), their popup fires on its own with that condition's icon centered on top of the portrait, sized by one global slider. If more than one qualifying condition lands on someone at the same moment, all of them show together in one popup instead of firing separately.

## Installing / updating it

1. Connect to the server with an SFTP client (FileZilla or WinSCP both work) on port 2225.
2. Find Foundry's `Data/modules/` folder on the server.
3. **This version renamed the module's internal id again** (`character-popup` → `fga-character-popup`), so Foundry sees it as a brand-new module, not an update — delete the old `Data/modules/character-popup` folder first (its settings will reset), then upload this `fga-character-popup` folder into `Data/modules/`, so you end up with `Data/modules/fga-character-popup/module.json` on the server.
4. In Foundry, as GM, go to **Game Settings → Manage Modules**, uncheck/remove the old "Character Popup" if it's still listed, check the new "FGA Character Popup", and save.

## Trying it out

1. As GM, open **Game Settings → Configure Popup Rules** and set the duration (or "no timeout"), which message types trigger it, and the bloodied/healed/revived aura settings.
2. As GM, open **Game Settings → Configure Character Appearance** to set the Shared Default look every player character uses, an NPC disposition group's look, or a custom look for one specific character — pick a target on the left and adjust the fields on the right (NPC buckets and individual characters also have a Mode selector to switch into "override").
3. As GM, open **Game Settings → Configure Status Icons** to turn on the buff and/or debuff master switches and adjust any condition's classification, then set the icon size.
4. As any player (or the GM) with a character assigned, open **Game Settings → Configure Your Popup** to choose portrait vs. token image and your character's own chat bubble color — the read-only portrait preview shows your character at its current GM-set size/position/flip, and the bubble preview updates live as you pick a color. "Text color: auto" is checked by default (exact inverse of the bubble color); uncheck it to pick your own text color instead, if the auto-inverse looks off on your chosen background. The note under Image Source tells you if the GM has pinned a specific image for your character right now. Everyone else at the table will see that same bubble and text color whenever your character speaks.
5. Send a chat message while speaking as a character with an assigned token/actor (Po Tato is a good test — it already has portrait art set up). The popup should appear wherever configured. To test status icons specifically, apply a classified condition to a token from its token HUD (right-click the token, or select it and use the condition icons along its edge) and watch for the popup to fire on its own.

- **`2026.09.24.1`** — compatibility check after Mogie updated the Dev server to Foundry VTT **V14** and the module stopped working. - **`2026.09.24.2`** — live-tested `2026.09.24.1` directly against Mogie's V14 Dev server via a connected browser session. Module Management showed it active with no compatibility warning, `Initialized` logged cleanly, and its settings windows all rendered fine — but bloodied/healed/revived/status-icon popups worked while **speaking in chat showed no popup at all, for every character, with no console error either.**
  - **Root cause, confirmed live** by inspecting real chat messages in the browser console: Foundry **V14 added an explicit "speaking as" selector to the chat box**, and its default mode ("Public") sends the message with `speaker: {scene: null, actor: null, token: null}` — completely empty. Every earlier Foundry version auto-attached the sender's assigned character to `speaker` automatically; V14 no longer does unless the player explicitly switches that selector to "Public as Character." `getSpeakingActor()` had nothing to resolve, so `handleChatMessage` correctly (silently) declined to show a popup — no bug, just nothing to key off of.
  - **Fix:** `getSpeakingActor()` (`main.js`) now falls back to the message sender's own assigned character (`message.author.character`, or `message.user.character` on V12/V13 where the property is still named `user`) whenever `speaker.token`/`speaker.actor` are both empty — restoring the old auto-attach behavior without requiring anyone to touch the new V14 selector. A deliberately chosen speaker (a token, or "Public as Character") is still always used first.
  - Validated: `node --check` on `main.js`, confirmed via the live browser session that `message.author.character` correctly resolved to the sending player's actual character (Po Tato, for the message that prompted this investigation).
  - Mogie already confirmed live on the V14 Dev server, independent of this fix: bloodied, healed/revived, and status-effect popups all still work correctly. **This build's chat-trigger fix itself still needs the standard file-replace-and-restart, then a live re-test:** speak in chat as a normal player, as the GM with a token selected, and (if it comes up) with the new "speaking as" selector deliberately set to something other than the default, to confirm the fallback doesn't override an intentional choice.
